This is the normative protocol; the template records its application. Documentation, not executable workflows, runtime enforcement, implemented security, a calibrated metric or a convergence proof. Substantive judgement and designated acceptance authority remain necessary. Exactly one active task, one named drafter and one active candidate at any time; observers and reviewers may work in parallel without editing that candidate.

Structured environment

Scratchpad Beads is durable cross-agent memory and communication for intent, status, findings, decisions, uncertainties and evidence references. Workspace-local .scratchpad/ is an ephemeral adjunct, not an alternate codebase or authority. Its task owner records ownership, recovery pointers and retention deadline in Beads before use; promote necessary evidence to Beads before deleting only owned temporary files at task close or the recorded deadline. Interrupted work retains those recovery pointers; missing scratch files make dependent evidence Unknown. Ignore excludes default new-file tracking, not already-tracked files, forced additions, secrecy, backups or cleanup. Do not place secrets there; redact evidence before durable storage. Existing .ooda/ remains unchanged.

Current state Uniquely resolved exact accepted main commit: current authority, not proof of quality/historical substantive acceptance. Resolve refs/heads/main, not arbitrary checkout HEAD; record full commit ID and resolution context. Missing or stale accepted state is Unknown/Unresolved: never fall back to HEAD or a remote last-seen position.

History Git main, trunk-based; advancement follows authority.

Candidate One scoped Git candidate, bound to exact accepted main base/content identity. Transitional repository work, not a second codebase; snapshot/commit existence is not acceptance.

Use ordinary Git: inspect status, diff, staged diff and log; draft and run declared tests; review exact content; add explicit scoped paths and commit only when designated authority permits. No jj, candidate stack, feature branch, advanced Git plumbing, bespoke gate, lock, permission system or daemon is required. If candidate commits already exist, record their full IDs and introduced content, not merely a net diff. Changed candidate/base/context invalidates affected evidence and authorization. Preserve unrelated staged, unstaged and untracked work; unavailable identities remain Unknown. This cooperative workflow cannot prevent external copies, offline edits or noncooperating writers.

Only the repository is a codebase. Record scope/preserve unrelated edits; identify exact content, not filenames, by reproducible scoped path/change digest/snapshot including new files/deletions. See reconciliation/evidence derivation.

Seven review aspects

Use task-proportional concrete criteria and risk-based review strength, not compulsory recursion. Review targets concern their claims' evidence/coverage, not candidate assessment.

Assess all seven for applicability. For each record criterion, scope, applicable counterexample and Satisfied | Violated | Unknown; justify omissions and bind evidence through derivation. Checker errors, unavailable evidence and incomplete required coverage are Unknown, not satisfaction or a negative domain conclusion. Investigate unknowns when useful; a required Unknown blocks acceptance. A research gap may remain only with its claim excluded from acceptance, never as an established fact or evidence acquired through repeated review. See comparison for required-aspect protection.

Bind conclusions: claim/criterion → exact target/base/criteria/context identity → witness locator/result → witness-to-conclusion reasoning → uncertainty/applicability; locators alone are insufficient. Candidate/baseline/criteria/ evidence changes invalidate affected conclusions: refresh checks/derivations, including corrected reviews of unchanged candidates. Reuse requires exact unchanged content/context and a reason.

Adaptive lifecycle

Adaptive understand/change/verify is the default where designs collide, especially in high churn. These six positions organize work, not rigid runtime stages. Check failures and unknowns require disposition at 4, never direct acceptance. Any position may stop without acceptance and record its outcome at 6; this general stop rule is not an authorization shortcut.

  1. Frame and understand: name objective, audience, consequence, intent, scope, required criteria/revisions, protected obligations, roles and evidence context. Record repository/history/scratchpad references and use reconciliation. Rank consequential structures, symmetries and invariants with witnesses and counterexamples before polishing; local evidence can overturn that priority. Proceed to 2 when the proportional frame suffices for coherent work.
  2. Coherent increment: build significant reviewable work within intent and candidate scope; interleave useful checks, not substantive review per edit. When coherent go to 3.
  3. Check and assess: run declared checks and substantive evidence-based assessment against applicable aspects. Record scope/results/uncertainties/allegations for 4. Clean means no supported findings within examined content/context, not universal truth.
  4. Resolve findings and refine: per finding record stable ID, exact candidate/review target identity and location; allegation/criterion/consequence/priority; evidence/counterexample/disputed interpretation; named decision-maker and evidence-based rationale; Supported | Unsupported | Unresolved decision and disposition. Repair only supported changes with a new revision; reject unsupported allegations and record unresolved effects. Apply refresh/reuse. Continue repair or coherent construction at 2; revisit 1 if assumptions break within intent; finish rejected/unresolved at 6; otherwise use readiness for 5.
  5. Accept and advance main: apply the acceptance contract, then proceed to 6.
  6. Record outcome and select next task: record Accepted | Rejected | Unresolved, exact resulting accepted main commit, candidate disposition, findings, uncertainties and evidence references in Beads. Use reconciliation before selecting the next task at 1.

Within framing, select the two-axis catalogue: core techniques for all seven questions, applicable additional concerns and every relevant subject profile. Before assessment actually read selected guidance and applicable caller house style; record exact loaded path/content identity, reader/loading witness, applicability, derived criteria, limitations and conflicts. Protected protocol/authority obligations and explicit task constraints govern; binding local style precedes labeled provisional defaults and external advice. Resolve binding conflicts with the applicable decision owner, not silent substitution. Unsupported subjects or unavailable required guidance remain Unknown; core alone cannot silently stand in for missing subject techniques. Guidance/context changes invalidate affected conclusions and authorization through derivation. Selection/loading consumes shared precharged work, never protected return reserve. This is a reading/recording obligation within existing positions, not a runtime loader, new stage or acceptance actor.

Within 4 (no extra position), one compact record: exact candidate/base, current required evidence/conclusions, resolved required findings, remaining bounded-attempt acceptance credit/blockers. Eligibility: required criteria, supported repairs, protected comparison.

Criticism alleges, not automatically edits. Targeted review-of-review needs concrete doubt: unsupported evidence, contradictions, threatened obligations, disputed interpretation or consequential gaps. Inspect claim and consequences; no mandatory depth/repeated clean passes. Simple failures need compact disposition, not separate documents.

On resume/interruption reconcile exact actual main, candidate and scratchpad with evidence refresh/reuse; interrupted/partial advancement cannot assume an unchanged baseline. If main moved, reconcile—not overwrite—and obtain applicable authorization.

Bounded shared protocol credits

Before substantive work declare finite positive initial work and separate finite positive protected return reserve in scratchpad, bounded operation scopes and fixed positive heterogeneous prices. These are task-specific conventions, not time, energy or production-cost defaults. Framing, evidence gathering, orientation, edits, checks, substantive review, justified review descendants, adjudication, revalidation and acceptance attempts all consume work. All participants/attempts share one account: debit before each operation; failure/interruption retains the charge. No refunds or silent reset on retry, review, role change or resume. At its scope limit an operation stops; further work needs another affordable precharged operation.

At 80% of initial work consumed, or before an affordable proposed charge reaches or crosses it, strongly signal prepare-to-return; record reason and bounded closure plan, preferring justified closure over expansion. This never relaxes acceptance criteria/authority. Admit only affordable operations within intent. At zero work or insufficient remaining work, halt all new substantive work, including checks, repairs, review, adjudication and acceptance. A lawfully precharged bounded operation may finish; interrupted acceptance follows reconciliation.

The reserve funds only its predeclared bounded minimal outcome report, main/candidate reconciliation from existing records, findings/evidence pointers, accounting and upward return; not new evidence, repair, finding decisions or advancement. If acceptance has not occurred preserve main and the separate exact candidate (scoped content or existing candidate commits). If accounting/identity cannot be reconciled from existing records, report Unknown and stop, not invented spending permission. Resume retains initial allocations/every charge; later allowance needs explicit commander authorization and a recorded extension, never erased consumption. The reserve affords bounded reporting, not host availability.

Continuation records position/outcome, stop reason, exact main/candidate identities, evidence/uncertainty/findings, initial/spent/remaining work and reserve, next affordable action, and conditions/authority to resume.

Mission command

The commander sets intent/constraints/success criteria/allowance; the executor adapts creatively within them, reporting verified effects. Command differs from acceptance authority. Fleet mapping: Moltke owns tasking/re-decomposition/closeout; Hopper executes; evidence/orientation roles inform decisions. Not a compulsory roster or extra stage. Routine adaptation stays local; material strategic Surprise/Opportunity goes upward rather than silently expanding scope/credit.

A material BackBrief records trigger (Surprise | Opportunity), scope (OutsideMission | PackageLevel | SystemLevel), cited observation, intent_relevance, local_action, requested_response (Acknowledge | AdjustIntent | ReDecompose | EscalateToUser), confidence (high | medium | low). Requests recommend, not authorize; ordinary planned credit return is an outcome/continuation report, not a fabricated trigger.

Higher misalignment pauses for orientation before operator choices. Fleet-specific, not universal SCAR thresholds: two repeat same-defect rejections differ from new classes across >3 rounds or defensive scaffolding >2× core logic. At round three halt if edge-case layers accumulate. Commander obtains ≥2 ranked clean seams/tradeoffs, presents 2–4 structured operator choices/recommendation, then re-decomposes after selection. Doctrine, not calibration/runtime proof. Investigation uses work charges; without credit return friction/request decision, not free analysis.

Authority and ratchet

Name drafter/reviewer/finding decision-maker/designated acceptance authority and overlaps/limits; no drafter self-authorization. Record decision/limits and explicit standing authorization: may avoid per-step human decisions, but exact-content/ baseline/evidence requirements remain. Scratchpad corroborates, never confers acceptance or substitutes for an actual commit.

Compare protected per-aspect obligations compatibly; averages cannot hide required failures/prove preservation. Unknown comparability blocks existing-contract acceptance: resolve or separately authorize a changed contract without claiming old obligations hold. Prune redundancy, not protected obligations/mandated evidence/history.

Designated authority authorizes exact candidate content, expected exact main baseline, criteria/evidence context and scope from readiness. Changes to candidate/baseline/criteria/evidence invalidate affected authorization; conclusions follow derivation. Recheck those identities/context/scope and authority before the verified authorized advancement of main, respecting scoped edits and task operation limits. Candidate commits can already exist: creation is not this acceptance boundary. Agree on one cooperative drafter; parallel observers/reviewers do not write the candidate. Recheck actual accepted main, expected baseline, candidate, staged content and context before authorized ordinary Git add/commit. No race-free acceptance or implemented exclusion is claimed; unexpected writers/main movement require reconciliation, not overwrite. After advancement confirm exact content and uniquely resolved resulting accepted main commit before claiming Accepted, never merely from intent. Commit/push forbidden or authority absent means preserve the candidate without advancement. Denied/stale/interrupted acceptance is Unresolved; rejected/unresolved candidates do not advance through this protocol. Use reconciliation for interruptions/main movement.

Edits-only or candidate commits: verified work awaits review/designated advancement authority, not Accepted. First acceptance requires eligibility even without past main quality evidence; syntax alone is insufficient. Corrections append authorized commits, never erase decisions; mistaken acceptance needs a new corrective task.

Environment and component description

The outer Structured environment shows the chapter's four components: Scratchpad, Current state, History and Candidate. Only the repository is a codebase: record scope, preserve unrelated edits and identify exact content by reproducible scoped digest/snapshot, including new files and deletions. The six numbered lifecycle positions and their transition conditions are documentary protocol guidance, not six implemented services. Repository components do not add lifecycle positions or acceptance actors.

  • Scratchpad: Beads stores durable cross-agent records; owned workspace-local .scratchpad is an ephemeral adjunct under the environment's retention/recovery/secrets limits. Neither confers acceptance authority.
  • Current state: uniquely resolved exact accepted main commit is current authority, not arbitrary HEAD or proof of historical quality.
  • History: Git main, trunk-based; advancement follows authority.
  • Candidate: one scoped Git candidate with exact accepted base/content; one drafter, parallel observation/review, transitional and not Accepted merely because committed.
