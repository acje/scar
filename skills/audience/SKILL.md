# Audience usability and accessibility

## Applicability
Use when people must understand, navigate or act on an artefact. Name audience, capabilities, task, delivery medium and adopted access requirements; usability and accessibility are related but not interchangeable.

## Techniques
1. Walk the named task from entry to completion: locate options, interpret audience language, observe status, prevent consequential mistakes and recover from errors. Prefer visible cues over memory demands.
2. Inventory meaningful non-text information, relationships, reading sequence and non-color cues; compare the equivalent accessible representation.
3. Use the relevant subject profile to choose actual output/interaction checks. Distinguish heuristic inspection from observed participant, keyboard or assistive-technology tests.

## Evidence and output
Record audience/task steps, observed obstacles, exact delivery identity, adopted criterion and witness. State what was inspected versus exercised and why a result supports task access/success. Map results to correctness, structure or accuracy as appropriate; add this concern row when scoped.

## Limitations
Heuristics do not prove user success. Static text or checker success does not certify accessibility. Web WCAG applicability and conformance level require task adoption; offline formats are not silently subject to every web criterion. Unperformed required checks remain Unknown.
